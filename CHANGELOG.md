# Changelog

All notable changes to this project are documented in this file.

## [Unreleased]

### Added
- **OMP config directory** — Under OMP, store the global config at `<agentDir>/automode/config.json` and project config at `.omp/automode.local.json` and `.omp/automode.json`. `<agentDir>` comes from OMP's `getAgentDir()`, so profiles and `PI_CONFIG_DIR` apply. A Pi global config moves there once at startup, with ADR-002 conflict and error handling. When the agent directory is on another filesystem, the move copies the file into place and then removes the legacy one. Project files fall back to `.pi/` per file when `.omp/` lacks them and are never moved. In-memory session logs go to `<agentDir>/automode/logs/`. `/automode config` and `automode_inspect` report the selected files as `configSources`. Pi keeps its existing paths. See ADR-003.
- **OMP safety-control paths** — Hard-deny direct writes and edits to `.omp/automode*`, `<agentDir>/automode/`, and `<agentDir>/extensions/`, as `.pi/automode*` and `~/.pi/agent/extensions/` already are. Add `.omp` to the default protected paths.
- **`permissions.ask` in subagents** — A `permissions.ask` match in a session without UI, such as an OMP subagent, used to block the call. The new `autoMode.headlessAsk` setting chooses what happens: `parent` (default) shows the dialog in the nearest ancestor session of the same process that has a UI, titled with the asking agent's name, and blocks the call when nobody answers within 25 seconds or no ancestor is found; `classifier` skips the question and sends the call to the classifier with a note that the rule matched in a session without UI; `block` keeps the previous behavior. Shared project `.pi/automode.json` cannot set it.
- **Agent Hub entry on OMP** — Each session registers a read-only `<agent>-automode` entry (`main-automode`, `Pr32Drawbacks-automode`) in OMP's Agent Hub (`/hub`). It shows `running` with the action being classified, and rests as `parked` with the latest decision. The entry is an advisor, so it stays out of IRC rosters and the running-subagent badge, and it is removed at session shutdown. Pi has no hub and is unaffected
- **Richer `automode_inspect` status** — `status` now reports the kind of the last decision (never its reason), where the enabled state came from (config scope, `/automode` override, or inherited from the parent agent), the agent identity and `hasUI`, and the last 12 classifier provider errors as typed kind, stage, timestamp, and model. Provider error text and payloads stay out of the model-visible output.
- **Decision log fields** — `decision` entries gain `durationMs`, `stage` (`permissions`, `hard-deny`, `path`, `inside-cwd`, `url-scheme`, `allow`, `read-only`, `classifier-fast`, `classifier-detailed`), `agent` (`id`, `name`, `kind`), and `hasUI`. A fail-closed classifier block also records `errorKind` and, when the provider sent one, `retryAfterMs`. The fields are additive; older readers are unaffected.
- **`automode_inspect` calls are logged** as `read-only` decisions. They still change no counters or state.
- **Paths created by the session reach the classifier** — Auto mode now records the paths that the session's own `mkdir`, `mktemp`, `git clone`, `gh repo clone`, `git worktree add`, and new-file `write` calls created. It lists up to 30 of them in a `<session-created-paths>` block after the transcript. Cleaning up such a path no longer looks like deleting files that existed before the session, even after the creating call left the transcript window. A call is recorded only after it was allowed and returned without an error, and only for paths that did not exist before it ran. The last 100 paths persist in the `pi-automode-state` entry and survive `/resume`. The list is evidence for the classifier only: it does not bypass `permissions.deny`, hard-deny checks, `deniedPaths`, protected paths, or the classifier's other deny rules.
- **OMP model roles for the classifier** — `classifierModel` accepts OMP role selectors such as `@smol` and `@judge` next to `provider/model-id`. A role resolves to OMP's own chain for that role, including its cross-provider fallbacks, and the classifier uses the first chat-capable model that has credentials. Under OMP an unset `classifierModel` now means `@smol` (falling back to the session model when that role resolves to nothing); Pi still defaults to the session model. `/automode model @role`, `/automode status`, `/automode config`, and `automode_inspect` show the selector and the model it resolves to.
- **Classifier fallback and typed failures** — Classifier errors are typed (`rate-limit`, `timeout`, `server`, `auth`, `invalid-response`, `context-limit`, `no-classifier`, `aborted`). A timeout or server error is retried once after a short jittered pause. On a 429, credential failure, or exhausted retry the classifier moves to the next model in the OMP role chain, preferring another provider. A 429 puts the provider on a cooldown that honours `retry-after` (capped at 10 minutes), so repeated actions do not hit a throttled account. When no model can decide, the block has the new kind `classifier-unavailable` and a reason such as `classifier unavailable (rate limited, retry in 53m)`, separate from policy denials and not counted as one. `/automode reload` clears the cooldowns.
- **OMP `eval` analysis** — `permissions.deny`, `permissions.ask`, and `permissions.allow` now accept `eval(...)` patterns matched against the cell code, optionally scoped as `eval(py: ...)` or `eval(js: ...)`. Literal shell commands in Python (`subprocess.*`, `os.system`, `os.popen`, IPython `!cmd` and `%%bash`) and JavaScript (`child_process`, Bun's `$` and `Bun.spawn`) are extracted and run through `bash(...)` rules and the deterministic hard-deny checks. Code with commands the scanner cannot read (f-strings, variables, `getattr`, `__import__`, `exec`, aliases, and similar) is opaque: it never matches `permissions.allow`, never uses the fast classifier stage, and the classifier is told why. The scan is lexical and best-effort, not a sandbox. In 564 real `eval` calls, 83 contained subprocess, `rm -rf`, `git push`, or `gh pr create` text that no pattern could match, and 22 evals were fast-allowed.
- **Read-only Bash tier** — New opt-in `allowReadOnlyBash` (default `false`). A Bash command skips the classifier when static analysis shows it only reads files: allowlisted binaries and flags, static words, no redirects except `/dev/null`, no command substitution, no environment prefix, and every path checked against `deniedPaths`. Commands that write, run another program (`sed -i`, `find -exec`, `rg --pre`, `git -c`, pagers), or cannot be analyzed still go to the classifier. In one log of 6,929 Bash calls, 18% qualified, and none of the qualifying calls had been blocked by classifier policy.
- **`readOnlyRoots`** — New opt-in list of absolute directories (default `[]`). `read`, `grep`, `find`, and `ls` calls inside a root skip the classifier outside the working directory. `deniedPaths`, protected paths, and symlink resolution still apply, and `write` and `edit` never use roots. Entries such as `/`, the home directory, and system roots are rejected. Neither setting can come from shared project `.pi/automode.json`.
- **Classifier strategies and a hybrid judge** — `classifierStrategy` is `staged` (default, unchanged), `detailed` (skips the one-token gate, which passed 14% of actions in the logs and cost more time than it saved), or `hybrid`. Under OMP, `hybrid` first asks the `judge` role chain four typed policy questions and approves only when the safe-side probabilities reach `judgeConfidence` (default 0.9); anything else, including judge errors, escalates to the detailed classifier on `classifierModel`. The judge never blocks, is skipped for `permissions.ask` actions and `eval`, and its cost is logged. Only a calibrated native judge (TypeSafe Jev) can approve: prompted chat models answer one-hot, so `judgeConfidence` cannot gate them, and on-device models are too weak. Both are skipped, and a chain without a native judge logs `judge-unavailable: no calibrated judge` and goes to the detailed classifier.
- **Settings menu and OMP model picker** — `/automode settings` opens a menu for `enabled`, `classifierStrategy`, `classifierModel`, `judgeConfidence`, `classifierReasoningLevel`, and the two log switches. Each row shows its effective value and where it comes from (default, global file, project-local file, `PI_AUTOMODE_SETTINGS_JSON`, or the session's `/automode on|off`). Choices are saved to the global config with its other keys intact, and a save says when a higher-precedence source keeps another value in effect. Under OMP, `/automode model` without an argument lists the model roles and opens OMP's native model picker in selection-only mode; Pi keeps its model list. The judge model stays an OMP setting (`modelRoles.judge`) and the menu points to it.
- **OMP 19.1 tool commands** — OMP 19.1 runs tools such as `lsp` and `github` as Bash commands, which fires a `tool_call` for the `bash` call and another for the wrapped tool (`<bash id>:cmd:<n>`). The `bash` call is reviewed as usual, and a new default allow rule lists the tool commands that only read. When the classifier allows the `bash` call, the wrapped call skips the classifier and logs as `tool-command`; permission rules, hard-deny checks, and `deniedPaths` still apply to it. The wrapped call is classified when the `bash` call passed through a deterministic tier, the script does not name the tool literally, or the `bash` call has already returned. A Bash call that only runs `automode_inspect` keeps the inspection tool's classifier exemption.
### Changed
- **Compact status segment** — The status is now one segment with an icon: `<icon> auto`, `<icon> auto · N blocked`, `<icon> off`, and `<icon> checking…` while a classifier call is in flight. On OMP the icon is the theme's shield glyph, falling back to `icon.auto`; Pi shows `●`. The `a:`/`d:`/`ca:`/`cd:` counters moved out of the status; `/automode status` still reports them. The README explains how to place the status inside OMP's status bar and why `statusLine.showHookStatus: false` avoids a duplicate row
- **Recursive `grep` runs around denied paths** — A `grep` whose root can reach a `deniedPaths` entry is no longer blocked outright. For OMP's built-in `grep`, pi-automode appends `!glob` exclusions to `path` (list entries OMP's grep already understands), so denied files are never searched, and it drops a result whose file list contains a denied file. It still blocks the call when the exclusions cannot be guaranteed, for example when a pattern covers the whole search root, and it still blocks `find` and any `grep` that is not OMP's built-in. In one decision log this blocked a legitimate `grep` of `~/.omp`; a `find` of `/home` is still blocked.

### Removed
- **`/auto-mode` command alias** — Only `/automode` is registered. Previously both names appeared in command completion with identical behavior
### Fixed
- **`/tan` clones run auto mode** — OMP never emits `session_start` for `/tan` clones, so a clone kept the factory defaults: the main session's `/automode on|off` did not reach it, project configuration was ignored, and persisting state threw "Extension runtime not initialized" so every action in the clone failed. Auto mode now initialises a session on its first `before_agent_start` or `tool_call` when `session_start` has not run, using the session's own working directory and project trust. Subagents find their parent by session file or session id, because a clone's header names its parent by id. The auto-mode guidance is no longer added to a system prompt that already contains it, and it extends OMP's block-array system prompts as its own block. Counters and state of a clone stay in memory.
- **`scheme://` paths were treated as files in the working directory** — `xd://propose`, `https://example.com`, `skill://github` or `local://notes.md` resolved to `<cwd>/xd:/propose` and passed the inside-working-directory tier, and the logged reason named a path that does not exist. In one decision log this was 1,861 of 11.9k decisions. Pi-automode now splits a file tool's path into URL and filesystem entries before it resolves anything. Reads of built-in OMP schemes (`skill`, `local`, `artifact`, `omp`, `history`, `issue`, `pr`, `mr`, `agent`, `proc`, `mcp`, `xd`) are allowed locally with decision kind `url-scheme`. `http(s)`, `ssh`, and unknown schemes reach the classifier, which closes URL reads as an outbound channel even when `classifyReadOnlyTools` is off. A write to `xd://<tool>` is allowed because the nested tool call is judged on its own. A write to `local://` follows `allowInsideWorkingDirectory`; writes to `proc://`, `agent://`, and other schemes reach the classifier. `permissions.allow`, `ask`, and `deny` rules match URLs as typed.
- **OMP read selectors and path lists bypassed `deniedPaths`** — `read` and `grep` paths such as `~/.netrc:1-2`, `~/.config/gh/hosts.yml:raw`, `~/.ssh/id_ed25519:1+5`, `app.db:table:key`, `file.json?q=…`, `a;~/.netrc` and `:~/.netrc` resolved to a different file than the one OMP opened, so they skipped `deniedPaths`, `permissions.deny` read rules and the inside-working-directory tier. Pi-automode now checks the typed path, every list entry, and every prefix before a `:` or `?`. Allow tiers need every one of them to pass. Real file names with colons still match literally.
- **Directory-change order in hard-deny checks** — A `cd`, `eval`, `source`, or dynamic command name that cannot be resolved now affects only the commands after it, instead of every relative deletion, permission change, or redirect in the script. Paths that start with a variable (`$d/out.yml` after `d=$(mktemp -d)`) no longer count as relative to an unknown directory; they are checked as if the variable were empty. Commands in loops and functions are still checked against every directory the script can reach, and a relative `cd` in a loop stays unresolved. This stops blocking `cd /tmp; rm -rf hd2; git clone … hd2 && cd hd2 && …`, `mkdir -p ~/.omp/wt && cd ~/.omp/wt && rm -rf work && gh repo clone … work && cd work`, and a whole script wrapped in `eval '…'` that writes to `$d/gen.yml`, three commands the deterministic check blocked in real sessions without classifier review. Commands that follow an unresolved directory change stay blocked.
- **Read-only `git` ran repository-configured programs** — With `allowReadOnlyBash`, `git status`, `git diff`, `git log -p` and similar commands skipped the classifier even when the repository's `.git/config` set `core.fsmonitor`, `diff.external`, a `textconv` or `filter` driver, or an `include`, so git ran that program unreviewed. Such repositories now send `git` to the classifier.
- **Long latest user messages lost their middle** — The latest human message was cut to 1000 approximate tokens like every other entry, so long feedback reached the classifier without its middle and actions it asked for were blocked. It may now use up to half of `maxUserTranscriptTokens`.
- **Project instructions could forge transcript evidence** — `AGENTS.md` and other loaded context files were inserted unescaped, so a repository file could close `<loaded-project-instructions>` and add records that looked like user messages. Their `<` characters are now escaped.
- **Classifier evidence provenance** — Serialize transcript evidence as JSONL records with explicit provenance and escaped content, so embedded labels or record-like text cannot create human records. Truncate content before serialization and mark omitted evidence without breaking record boundaries.
- **Subagents follow `/automode on|off`** — OMP subagents now use the main session's `/automode on` or `/automode off` choice, including subagents that are already running. Previously each subagent used the configured `enabled` value, so subagents kept blocking after `/automode off`. Under `--no-session`, subagents still use the configured value.
- **Worker authorization evidence** — Retain human instructions and verified ask answers from live OMP ancestor sessions without treating agent-authored assignments as human consent. Preserve branch order, merge sources by valid timestamps with deterministic missing-time and tie handling, prioritize human intent within transcript budgets, and exclude forks, switched-away parents, and unavailable parents. Ancestors are found by session file or session id, so `/tan` clones are covered.
- **Human evidence budgets** — Reserve space for human intent anchors before delegated assignments and reuse unspent space. Short assignments no longer truncate human revocations when the complete evidence fits the transcript budget.
- **Classifier false positives** — Read bounded authorization across human messages and evaluate the current security risk rather than code quality or prior denials. Distinguish non-secret local SQLite diagnostics from production mutations and external disclosures without bypassing hard-deny rules.

## Fork features
- **Self-protection targets the running copy** — The classifier prompt now lists the active controls: the loaded extension's real paths, the global and project config files for the call's working directory, and whether `PI_AUTOMODE_SETTINGS_JSON` is set. `hard_deny` self-protection covers those paths. Other copies of the extension's source, such as a git clone or worktree, are ordinary project code, so editing one for a pull request follows the normal soft-deny rules and user intent. Previously the classifier hard-denied such edits because the default rule did not say which files were the running extension. The default `hard_deny` rule, a new allow exception, and the prompt examples state the scope. The scoping rule is part of the fixed prompt, so replacing `hard_deny` does not remove it. If the loaded extension directory is a git checkout (`omp -e <checkout>/extensions/auto-mode.ts`), that checkout stays protected
- **Source checkouts are no longer deterministic safety-control targets** — The deterministic checks denied any path under a directory named `pi-automode`, any `sed`/`cp`/`mv`/`rm`/`tee`/interpreter command whose text contained `pi-automode`, and any file in the working directory whose name contained `auto-mode`. A clone named `pi-automode`, `rm -rf …/pi-automode-scratch`, or `extensions/auto-mode.ts` in a checkout used as the working directory was blocked. The checks now protect the loaded extension's entry file, source directory, and vendored parser by real path (including through symlinks and `cd`), the `extensions/pi-automode` install-directory name, and legacy `auto-mode*.json` config names
- **Hard-deny reads every omp edit target** — File-tool checks now also read OMP's `paths` field for multi-file edits, `apply_patch` file headers, and hashline `MV` destinations, not only `path`

## Fork features

- Fork `czottmann/pi-automode` as `royce-mathew/omp-automode`, preserving Carlo Zottmann's attribution and the upstream MIT license.
- Add optional native TypeSafe Jev classification with `TYPESAFE_API_KEY` and `classifierModel: "typesafe/jev-latest"`. Keep Pi/OMP providers and the session-model default available.
- Validate typed policy answers and preserve hard-deny precedence, soft-deny exceptions, bounded authorization, full-action evidence, cancellation, and fail-closed request deadlines.
- Add an OMP marketplace catalog and explicit runtime extension manifest for Git or local marketplace installation.
- Count answers from OMP's built-in `ask` tool as classifier authorization evidence. Record only answers whose tool provenance is `<builtin:ask>`, keep them in transcript order, and exclude timeout auto-selections, chat redirects, errors, nested calls, and answers whose results left the active context.

## Bug fixes

- **Development dependency security** — Pin the Pi development packages to 1.0.1, replacing the older shrinkwrapped dependency tree that retained vulnerable `brace-expansion` 5.0.9. The development tree passes `npm audit` without overrides.
- **Directory-change path protection** — Check relative Bash targets against possible working directories after `cd`. Fail closed for sensitive relative operations when directory changes cannot be resolved.
- **Directory-change false positives** — Check only redirects that open a file for writing. `2>&1`, `>&-`, here-documents, here-strings, and input redirects no longer count as relative write targets after an unresolved `cd`. Track absolute `cd` targets inside loops and functions; relative `cd` there still stays unresolved. Replaying the 48 commands this rule blocked in real sessions now blocks 7, each with a dynamic, sourced, `HOME`-reassigned, or bare-name (`CDPATH`) directory change.
- **Persistence-path symlinks** — Protect shell profiles and SSH authorized keys through direct, chained, and parent-directory symlinks, including symlinked protected files.
- **Executable expansion checks** — Block pathname-expanded executable names and decoded NUL shell words before permission allows or classifier decisions. Preserve quoted glob literals and wildcard permission patterns.
- **Marketplace dependency delivery** — Include the pinned Bash parser and its ISC license in the Git tree. Validate native Jev answers without TypeBox submodules that OMP does not provide.
- **System-wide delete checks** — Block recursive deletion of `/Users` and its subdirectories. Check the search root after `find -H`, `-L`, or `-P` before `-delete`.
- **Codex classifier shutdown** — Codex classifier requests no longer keep session WebSockets. This lets `pi -p` exit after classification. These requests no longer reuse the prompt cache. (#60)

## [1.17.0] - 2026-09-22

## New features

- **Schema-constrained classifier decisions** — Return detailed-stage decisions through an internal `classifier_decision` tool call. Supported providers enforce the schema during generation, and pi-automode validates every returned call locally. When strict tool sampling is available, this reduces fail-closed blocks caused by malformed or contract-invalid decision JSON. (#50)
- **[Permission recipes](docs/permission-recipes.md)** — Add safe, composable examples for Bash permissions, working-directory changes, command chains, redirects, and classifier guidance. Thanks to @georgesleen for the impulse! (#46)

## Bug fixes

- **Status indicator separator** — Add one space between the `AM` prefix and the status symbol.
- **Classifier context budgeting** — Estimate fast and detailed classifier requests in tokens instead of mixing UTF-8 bytes with token limits. Check detailed-stage capacity only after the fast stage requests review. Large project contexts no longer block small actions that fit. (#37)
- **Explicit blocked-action feedback** — State that blocked tools did not run. Tell the agent not to claim success or rely on blocked effects. Require a report before dependent work continues. (#38)
- **Shared classifier reasoning reserves** — Use OMP 18 Anthropic reasoning budgets for classifier context checks under Pi and OMP. Reserve 4,096 tokens at `low` and 32,768 tokens at `xhigh` and `max` for all classifier providers. (#51)
- **Pi 0.86 classifier compatibility** — Route explicit-reasoning classifier calls through the model registry's normalized streaming API. Keep direct-provider support for older Pi versions and the compat fallback for OMP 18. (#52)
- **Dynamic Bash allow coverage** — Route commands with unresolved Bash argument expansions or active pathname expansions to classifier review. Preserve static quoted, escaped, and ANSI-C glob literals. (#54)
- **Classifier model validation** — Reject non-string and malformed `classifierModel` values during diagnostics and configuration merging. Preserve valid lower-precedence values and the session-model fallback. Prevent invalid configuration from causing tool-hook exceptions. (#55)
- **Malformed permission deny diagnostics** — Report malformed `permissions.deny` patterns with their configuration source and list index. Preserve fail-closed deny matching and no-match allow behavior. (#56)
- **Cancelled tool-call accounting** — Route already-cancelled calls through the standard block path. Record counters, denial history, persisted state, UI updates, and decision logs without Bash analysis or classifier work. (#57)

## Bug fixes

## [1.14.0] - 2026-08-27

## Bug fixes

- **Classifier stream timeout** — Apply `classifierTimeoutMs` to the full response stream. Provider behavior cannot keep classifier calls pending after the deadline. Parent cancellation remains active. Reject values above the Node.js timer limit. (#30)
- **OS temp-directory deletes** — Stop hard-denying recursive-delete subtrees under `os.tmpdir()` and `/tmp`. On macOS these resolve into `/private/tmp` and `/private/var/folders`, which matched the `/private` system root and blocked every temp cleanup. Deleting a temp root itself stays blocked. (#31)
- **Validated temp-root declarations** — Derive the exempt temp roots only from launcher-declared values that stay safe: reject values such as `/`, empty strings, aliases of `HOME`, `/`, or a system root, and ancestors of `HOME`. Without validation, a malformed `TMPDIR` could disable deterministic denials for protected targets, and a broad `permissions.allow` rule could then allow the action without classifier review. Recompute candidates when the effective tmpdir changes. (#31)

## [1.13.0] - 2026-08-25

## New features

- **Bash AST analysis** — Replace handwritten shell parsing with `unbash`. Permission and hard-deny checks now inspect command structure, nested commands, wrappers, redirects, and malformed input. Bash allow rules require complete structural coverage and fail closed when analysis is unsafe. (#26)
- **Extension-owned global config** — Store global settings at `~/.pi/agent/extensions/pi-automode/config.json`. Migrate the legacy file automatically, preserve a safe fallback after migration errors, and report conflicts through notifications and diagnostics. (#27)

## Bug fixes

- **Conservative permission rules** — Malformed deny and ask patterns block actions. Malformed patterns do not expand allow rules. Permission checks examine each Bash subcommand and normalize whitespace. Path checks resolve symlinks and normalize `file://` and Windows paths. (#22)
- **Recursive deletion hard-deny** — Detect uppercase flags and GNU abbreviations for recursive `rm`, including commands behind `command`, `exec`, and `env`. Parse the `--` delimiter and shell tilde expansion. Protect Linux and macOS system roots without blocking active-home subdirectories, `/opt`, or `/srv`. (#23)
- **Global Pi safety-control paths** — Hard-deny direct writes and edits to `~/.pi/agent/extensions/`, `~/.pi/agent/settings.json`, and `~/.pi/agent/settings/`. Resolve case variants and symlink targets before matching. (#24)
- **Case-insensitive protected paths** — Match protected paths without case distinctions and normalize Unicode spellings. This closes path bypasses on case-insensitive filesystems. (#25)

## [1.12.0] - 2026-08-23

## New features

- **Deterministic permission allows** — Add user-owned `permissions.allow` patterns that skip classifier review after deterministic checks pass. Accepted ask rules still require classifier review. Thank you, @sergeykonkin! (#14)
- **Configurable classifier request timeout** — new `autoMode.classifierTimeoutMs` setting. The default is 20000 ms. The timeout applies to each classifier request. The fast stage and the detailed stage each have their own budget. A request that exceeds the timeout is aborted. Auto mode fails closed and blocks the action.
- **Read-only agent diagnostics** — Add `automode_inspect` tool for status, configuration, defaults, and recent denial metadata. Thank you, @blalor! (#11)

## Bug fixes

- **Reject invalid config values** — Invalid boolean and log config values (e.g. `enabled: 0`, `log.enabled: 1`) are now rejected at merge time instead of being applied with diagnostics only. (#20)
- **Preserve defaults for malformed rule lists** — A malformed `hard_deny` entry like `[42]` no longer strips all built-in hard-deny rules. Malformed entries are rejected and defaults preserved conservatively. (#21)
- **Runtime classifier providers** — Dispatch classifier calls through Pi's runtime model registry so providers registered with `pi.registerProvider()` work immediately. Preserve normalized reasoning and header-only authentication on the temporary simple-completion bridge. (#15)
- **Bounded wildcard matching** — Replace regex-based permission and denied-path globs with a linear-time matcher. Reject oversized patterns and fail closed for oversized runtime inputs. (#19)
- **Complete classifier action input** — Send the exact current tool input to both classifier stages in a dedicated message. Block the action if it cannot fit without truncation. (#17)
- **Path policy normalization** — Use Pi-compatible resolution for file-tool paths, including file URLs, `@` and tilde aliases, and read fallback names. Enforce denied paths across omitted and recursive search scopes and both sides of symlink aliases. (#18)
- **Project config trust gate** — Ignore `.pi/automode.local.json` and `.pi/automode.json` until Pi trusts the project. Apply the trust gate during startup and config reloads. (#16)
- **In-memory observability logs** — Write logs to an extension-owned directory (`~/.pi/agent/extensions/pi-automode/logs/`) instead of the launching project directory. Thanks, @HerbertGao! (#13)
